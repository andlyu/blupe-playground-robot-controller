# SO101: LeRobot Python configuration

SO101 uses LeRobot's `SO101FollowerConfig` and Python `SOFollower` implementation.
There is no C++ driver or compiler requirement. LeRobot handles servo IDs,
calibration, Feetech communication and configured relative-target clipping.
BluPe supplies the operator panel and maps joint targets/observations.

## Configure

Install with Python 3.10–3.12:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[so101]'
```

Use a LeRobot robot JSON configuration (or the `robot` section of a run config):

```json
{
  "type": "so101_follower",
  "id": "YOUR_CALIBRATION_ID",
  "port": "/dev/tty.YOUR_FOLLOWER",
  "calibration_dir": "/absolute/path/to/calibration/robots/so_follower",
  "use_degrees": true,
  "disable_torque_on_disconnect": false,
  "max_relative_target": 5,
  "cameras": {
    "front": {
      "type": "opencv", "index_or_path": 0,
      "width": 640, "height": 360, "fps": 30
    }
  }
}
```

`id` locates `<calibration_dir>/<id>.json`; it is separate from the cloud robot ID.
`max_relative_target` uses LeRobot units: degrees for these arm joints, percentage
points for the gripper. Clipped actions are reported as `sent_action` in the panel.
The example retains torque on disconnect; setting the flag to true releases it
when closing an enabled controller. A read-only probe never changes torque.

```sh
.venv/bin/blupe-controller --config ./config.json setup \
  --hardware so101 --robot-id YOUR_CLOUD_ROBOT_ID \
  --api https://YOUR_SESSION_API --token-file /absolute/path/to/device-credential \
  --lerobot-config /absolute/path/to/robot.json
.venv/bin/blupe-controller --config ./config.json doctor
.venv/bin/blupe-controller --config ./config.json probe
```

BluPe stores a reference to this configuration and reloads it at startup; port,
calibration and camera definitions are not duplicated. OpenCV device indices,
per-camera resolution and frame rate are supported. Nondefault rotation/backend/
warmup settings are rejected rather than silently ignored. Cameras run in the
separate relay using this same configuration, so the motor-side LeRobot instance
has an empty camera map to avoid opening the devices twice.

## Operate

In separate terminals, run `blupe-controller --config ./config.json cameras` and
`blupe-controller --config ./config.json run`. Open `http://127.0.0.1:8096/`.
Ports can be set with `--operator-port` and `--camera-port` during setup.

Startup uses LeRobot's read-only bus connection, verifies calibration and position
mode, and reads observations. It does not run LeRobot's automatic configure or
calibration routines. **Enable** preloads the measured pose then enables torque.
**Move** forwards five degree targets and a 0–1 gripper value to `send_action()`;
LeRobot uses 0–100 for the gripper, so the adapter converts that field. Calibrated
position bounds are checked before sending. **Hold** writes the measured pose and
requires another enable before subsequent moves. **Capture zero** and **Capture home** save named poses persistently beside the
LeRobot config, in `<robot_id>.poses.json`. They read joints only and never change
calibration. **Move zero/home** passes through the same action path and clipping.
Saved poses are bound to the robot ID and calibration fingerprint; changing
calibration requires recording new poses.

To record from the terminal without enabling torque:

```sh
blupe-controller --config ./config.json record-pose zero
# Position the arm at the desired home pose, then:
blupe-controller --config ./config.json record-pose home
```

There is no independent watchdog or interpolation loop. If Python stalls, reads,
software checks and new commands stop; powered servos may continue to their last
target and hold it. Python cannot execute Hold during a stall. Servo firmware and
physical power removal determine behavior during a crash or communication loss.

The camera relay exposes MJPEG at `http://127.0.0.1:8089/0`, a fresh JPEG at
`/0/snapshot.jpg`, and freshness at `/status`. Grant macOS camera permission and
verify the intended camera. With real robot credentials, `publish-cameras` uploads
snapshots under that robot ID; it does not provide hosted HLS video.

The local operator can use an administrator-provisioned tunnel (`--local-port`);
set `--operator-hostname` to the hosted hostname. The hosted console serves a trusted
SO101 template and proxies owner-authorized controls and fresh JPEG previews.

## Cloud registration

Sign in to the Operator Dashboard, choose **Create/setup a robot**, and select
SO101. Its generated cloud robot ID and controller token are separate from the
LeRobot calibration ID. Save the token in the private file referenced by your
controller config. Set `settings.cloud_enabled` to `true` to connect on startup.
An administrator assigns the hosted route and authenticated reverse SSH tunnel.
The cloud API connection is outbound HTTPS/WSS on 443; it needs no tunnel.

The local panel shows cloud connection and queue state. **Accept next queued
task** requires an enabled arm at the captured home and a fresh camera; it permits
one session. Disconnect, stop or **Pause queue** revokes handoff and holds. Manual
movement is blocked while the cloud owns the arm. Startup never auto-enables or
auto-accepts tasks.

The bridge forwards five degree targets, an empty right-arm array and a 0–1
left-gripper value to LeRobot. It validates complete trajectories before dispatch,
checks leases and step order, reports progress, and waits for final feedback.
Commands clipped by LeRobot abort the cloud run instead of claiming the requested
target was reached. Send smaller steps within the configured relative limit.
There is still no software protection that runs independently of Python.

## Validation

`PYTHONPATH=src python3 -m unittest discover -s tests -v` checks read-only startup,
explicit enable, target mapping/limits, hold, configuration loading and panel
access controls with a mocked LeRobot robot. A separate local check constructed
the installed LeRobot robot and loaded calibration without opening hardware.
After restoring motor power and selecting the matching saved calibration, all six
servos responded and a zero pose was recorded. Physical motion and camera capture
have not been validated. No servo motion was initiated.
